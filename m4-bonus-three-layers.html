Bonus: Three Layers in Python

Open a small DataMan program in a Codespace. Change its screen text. Add one rule to its logic. Switch its storage from memory to a file. Show that each change stays in its own layer. Push your work to GitHub.

Why this bonus is here

Module 4 puts you back in Python. You still need your systems analysis. It tells you what to build. The code then tests that design.

Your Module 4 prototype has three layers: an interface, business logic, and a data layer. This bonus lets you work inside a small program with the same three layers first. You see the structure before you build your own.

You work on this in class. It is a bonus. It is also a beta test, because this is the first time we run it.

The three layers

Each box in the figure is one file. The interface is on top. The data layer is at the bottom.

┌──────────────────────┐
│ app.py               │
│ INTERFACE            │
│ text in, text out    │
└──────────┬───────────┘
           │            
┌──────────┴───────────┐
│ dataman/logic.py     │
│ BUSINESS LOGIC       │
│ the rules            │
└──────────┬───────────┘
           │            
┌──────────┴───────────┐
│ dataman/store.py     │
│ DATA                 │
│ a database stand-in  │
└──────────────────────┘

The figure shows three boxes in a column. The interface, app.py, shows text and takes input. It calls the business logic. The business logic, dataman/logic.py, holds the rules. It calls the data layer. The data layer, dataman/store.py, stands in for a database and calls nothing. One exception: app.py picks which data layer to use when the program starts, then hands it to the logic.

The steps in each segment add up to 40 minutes. The last 5 minutes are your buffer. Each segment ends with a push. Your instructor tells you when Segment 2 starts. Start it only after python check.py 1 passes.

How you end each segment

Push first. Then run the check.

git add -A
git commit -m "Bonus: finished a segment"
git push
python check.py 1        # use 2 at the end of Segment 2

The check reads facts that a machine can see. The tests pass. The library has no input() or print(). Your notes have no TODO. Your work is on GitHub. A passing check does not mean your answers are good. Your instructor reads your answers.

Caution

Do not edit any file in tests/. If a test fails, change the code, not the test. The check finds a changed test.

One rule about order

Plan first. Then execute. A gate stands between the two. Before the gate, you write down what you expect. After the gate, you run code and change files. You do not pass the gate until the writing is done.

The first gate is in Segment 1, step 2. You write four predictions in NOTES.md. Then you open the code. The second gate is in Segment 2, step 3.

Segment 1: run it, read it, change the interface

  1. Start · 5 min

    Open the template: bonus template repository [LINK PENDING]. Choose Use this template, then Create a new repository. Name it cts285-bonus-three-layers. Use the same sharing setting as your CTS-285 repository.

    Open the new repository. Choose Code, then Codespaces, then Create codespace on main. Wait for the terminal.

    Type pytest -q. You must see 9 passed.

  2. Predict, then find · 10 min

    Open NOTES.md. Find Part 1. It lists four actions. For each action, write the file that you think does it. Do this before you read any code.

    Gate. Do not edit any code until all four predictions are written.

    Now search. For the first action, type this command:

    grep -rn "Not yet" --include=*.py .

    Read the lines that appear. In the last column, write each file that the search found and what that file does. Replace the words in quotes with each of the other three search words, and search again.

    A search finds a word. It does not tell you which file does the job. You decide. Three of the four searches find more than one file. When that happens, say what each file does.

  3. Run it · 10 min

    Type python app.py. Type practice. Answer 55. Then answer 54. Type report. The report says two misses. Type quit.

    Type rm -f dataman_store.json. Type python app.py --store json. Type practice. Answer 55. Press Ctrl+C. An error message that ends with KeyboardInterrupt appears. This is normal.

    Type python app.py --store json again. Type practice. The prompt says Try 2. Press Ctrl+C.

    Open dataman_store.json. In NOTES.md, answer the two questions in Part 2.

  4. Change the interface only · 10 min

    Open app.py. Find the line that prints Not yet. Try again. Change the words. Save the file.

    Type pytest -q. You must still see 9 passed. Type python app.py, then practice, then answer 55. Read your new words. Press Ctrl+C.

    In NOTES.md, answer the two questions in Part 3.

  5. Push and check · 5 min

    Run the commands in the push block above. End with python check.py 1. If the check fails, it names the first problem. Fix that problem, push again, and run the check again.

Before you stop Segment 1

  • pytest -q shows 9 passed.
  • Every TODO in Parts 1 to 3 of NOTES.md has an answer.
  • I did not edit any file in tests/.
  • I pushed. python check.py 1 says All checks pass.

Segment 2: change a rule, break it, swap the data

  1. Restart · 3 min

    Go to your repository on GitHub. Choose Code, then Codespaces. Open the codespace you used. If none is listed, create a new one on main. Your work is on GitHub, so you lose nothing.

    Type python check.py 1. It must say All checks pass.

  2. Add a rule · 12 min

    Open exercise/bank.py. A Memory Bank set holds up to 10 problems. The rule is missing. Type pytest exercise -q. One test fails. Read the message.

    In add_problem, refuse the 11th problem. Raise SetFull. Do not edit exercise/test_bank.py. Run pytest exercise -q again. Repeat until you see 2 passed.

    Now open dataman/logic.py. Find the same rule in the real library. In NOTES.md, Part 4, write the file and the function name.

    Hint for the exercise rule

    A list has a length. len(self.members) tells you how many problems are in the set. Check it before you add.

  3. Break it on purpose · 10 min

    Gate. In NOTES.md, Part 5, write a guess: which test will fail? Write it before you change any code. After the run, correct the guess if it was wrong.

    Open dataman/logic.py. In add_problem, put # at the start of two lines: the line if len(current) >= MAX_SET_SIZE: and the line raise SetFull(...). Save the file.

    Type this command. It adds 11 problems to the set, one after the other:

    (for i in $(seq 1 11); do echo bank; echo P$i; done; echo quit) | python app.py

    Read the last line of the screen. Then type pytest -q. One test fails. Write what the screen showed and the name of the failed test in NOTES.md, Part 5.

    Restore the file: type git restore dataman/logic.py. Type pytest -q. You must see 9 passed.

  4. Swap the data layer · 8 min

    Open app.py. Find default="memory". Change memory to json. Save the file.

    Type rm -f dataman_store.json. Type python app.py. Type practice. Answer 55. Press Ctrl+C. Type python app.py again. Do not add a flag. Type practice. The prompt says Try 2. Press Ctrl+C.

    In NOTES.md, answer the two questions in Part 6.

  5. Reflect, push, check · 7 min

    In NOTES.md, write the Reflection: 3 to 5 sentences. Pick one layer. Say what you changed in it. Say what stayed the same in the other two layers.

    Run the push block above. End with python check.py 2.

Before you stop Segment 2

  • pytest -q shows 9 passed. pytest exercise -q shows 2 passed.
  • dataman/logic.py is back to its original text. git status lists no change in dataman/.
  • app.py says default="json".
  • Every TODO in NOTES.md has an answer, through the Reflection.
  • I pushed. python check.py 2 says All checks pass.
